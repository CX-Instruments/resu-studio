# Acceptance test: one application, end to end

Date: 2 September 2026
Ran against the repo at commit "Bring the documentation back in line with the code".

A reviewer was given SKILL.md, a fictional job advertisement (Senior Data Analyst,
Northbridge Water Corporation) and a fictional CV, and told to follow the instructions
exactly, play both sides of the conversation, and record every place the instructions
let them down. All seven phases completed. One command failed. Ten instruction defects
were found, several of which would hand a real person a wrong document.

The point of this test was the friction, so the friction is the report.

---

## What worked

- The data folder mechanism. One line in `~/.resu-studio/location` redirected everything,
  `paths.py` explained its own choice, and nothing leaked into the session's working
  directory across four studio builds and five renders.
- The typefaces. A `--pdf` run with no font flags embedded real Lora and Source Sans 3,
  subset, with no substitution and no network.
- The build reporting what it could not place: content with nowhere to go, proposals with
  no `Line:`, and proposals whose `Line:` names an id that is not on this CV.
- The dated keep on rebuild. The Phase 3 studio survived as
  `Senior Data Analyst - Studio (replaced 2026-09-02).html`, so the before score and the
  after score are both still on disk.
- The line count guard. It reported 31 in, 31 out on every render and listed the decisions
  separately, which is what made a double-apply hazard visible at all.
- `arithmetic.md` caught a real understatement on the first CV it saw: the profile claimed
  seven years against eight years and eight months elapsed.
- `achievements.md` caught a draft achievement resting on a bullet that a proposal was
  about to delete.

## Blockers found by the test

### T1. The instructions cannot produce a correct markdown master and a correct PDF at once

`SKILL.md:580` says the assembled `cv-<variant>.md` is written from the accepted proposals
and is "the deliverable and the master". `SKILL.md:726` says the render prints from the
markdown alone if the decisions file is skipped, so "every line they deleted comes back and
every rewrite reverts". `marking.md:61` and `achievements.md:5` say the markdown is never
touched by a removal, an addition or an added section.

These cannot all be true. Worse, `render_cv.py:920` appends additions unconditionally by id,
so baking everything into the markdown and then running the command that already carries
`--decisions` prints the added bullet twice and applies the reorder twice, and the line
count still balances, so nothing says so.

What the test did instead: baked only the text edits into the markdown, left removals,
additions, reordering and added sections to the decisions file, and verified both routes
render identically.

Cost as it stands: the file the skill calls the master still contains a bullet the person
deleted and is missing one they accepted. That is the file a person pastes into a portal.

### T2. Phase 1's first copy command fails on a fresh install

`cv_source_dir()` in `paths.py` is the only path function that does not create its folder,
so the first command of the first phase fails:

```
cp: cannot create regular file '.../cv-source/job-ad.txt': No such file or directory
```

### T3. The ATS table is wrong for the default layout, and the check it tells you to run fails

`ats.md:68` says `sidebar-dark` extracts as name, then sidebar, then main column, and
`ats.md:88` calls it a reasonable default whose only cost is a wrapped name. The measured
read-back interleaves the columns: the profile's second paragraph and the KEY ACHIEVEMENTS
heading are threaded through the middle of the skills block, which fails the file's own
check 3.

`ats.md:33` says not to hand over a document that has failed this check. Following the skill
and trusting its own table sends the interleaved file to the portal.

### T4. The decisions file cannot carry a rejection, and the pasted block cannot carry the achievements

`SKILL.md:511` offers the two return routes as equivalent. They are not.

`decisionsFile()` emits marks, adds, order and sections, and does not emit proposal
decisions. So a rejected proposal leaves no trace in `cv-decisions.json` at all, and a later
session would raise it again against an explicit no.

`handoffText()` lists ticked key achievements only when the person asked for a different
set, so someone who pastes the block and does not save the file hands over their work with
every ticked achievement missing.

### T5. Phase 6's render command has no `--decisions`, and writes a wrong file into the person's folder

Running `SKILL.md:650` as written wrote `cv-northbridge-sidebar-dark-forest.html` into the
documents folder containing the deleted bullet, no achievements and no added line. The later
`--pdf` run did not replace it, because with `--letter` the CV goes to a hidden print file
and the visible HTML is never regenerated. The person is left with a stale, plainly named
HTML sitting beside the correct PDF.

### T6. Two employers hiring the same job title share one studio file

`SKILL.md:236` says both `--role` and `--employer` are what tell two applications apart.
That holds for the PDFs. `build_studio.py:806` names the studio from the role alone, and
`documents.protect()` then sees the same role and the same source CV and does not intervene.

## Smaller instruction defects

- `voice.md:65` says a CV is written in the third person with no pronouns.
  `rewriting.md:105` says to keep the person the CV already uses. The test CV is first
  person. Nothing says which wins.
- Three files disagree on whether an eligibility line belongs on a CV: `templates/cv.md:4`
  and `assembling.md:21` allow it when the advertisement makes it a condition,
  `achievements.md:14` and `marking.md:161` say it belongs on the form.
- `check.py:151` decides a role has ended by reading the `###` heading only, so on a CV
  with the dates on their own line, which `render_cv.py` says is what almost everyone
  writes, no role is ever seen as ended and the past tense check never fires.
- `SKILL.md:302` says to record the depth in `answers.md`, whose template has no field for
  it.
- `templates/scorecard.md` has count keys for `must`, `nice` and `implied` but not for
  `condition` or `not a cv question`, which are both legal.
- `achievements.md:83` shows the field as `draws on` with a space. The parser only accepts
  `draws_on:`.
- `atomising-sources.md:216` says every published criterion is a `must`; SKILL.md says a
  licence or citizenship criterion is a `condition`. Criterion 9 of the test ad is both.
- There is no necessity value for a stated duty that is not a criterion. `implied` is
  defined as "not stated" and the studio labels it "From the role description", which is
  right for a duty list and wrong against the definition.
- `templates/proposals.md` has no group for "cut this to make room", which `rewriting.md:39`
  names as one of the shapes a useful change takes.
- SKILL.md's Phase 6 example uses `--palette forest` and its Phase 7 example uses
  `--palette navy`. Both documents are supposed to wear the same skin.
- `marking.md:146` says `--decisions` reports every change by id and wording. Rewrites
  apply silently.
- Three proposals in the test had no `Suggested:` text, because `rewriting.md:12` says the
  correct output is sometimes a question. `proposals_block()` drops any entry without one,
  so a question never reaches the studio.

## Also observed

- A nearly empty second page. The finished CV broke to page 2 for one role heading and one
  bullet, leaving about a fifth of page 1 blank and page 2 almost entirely blank. Worth
  looking at the paginator's widow rule.
- The shipped `source-sans-3-v19-latin-regular.woff2` identifies itself internally as
  `SourceSans3ExtraLight-Regular`, and that is the name that lands in the PDF. Two of the
  five typesets use it for body text. Worth confirming the file is the weight it claims to
  be.
- The studio still requests its own interface typeface from Google Fonts. The CV faces are
  embedded, so a document is never affected, but the studio's own chrome falls back when
  there is no network.
