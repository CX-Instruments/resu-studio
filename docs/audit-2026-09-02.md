# Resu Studio correctness audit

Date: 2 September 2026
Version audited: 0.3.0, as seeded into `D:\resu-plugin` from the installed plugin.

Five reviewers read the skill in parallel: the command-line contract, the render and PDF
pipeline, the studio builder, the written instructions as a body of rules, and the data
location logic. Findings below are grouped by what they cost, and every one carries the
file and line so it can be checked.

Line numbers are as at the seed commit.

---

## Blockers

These produce a wrong document or lose someone's work, and they fire on ordinary input.

### B1. No bundled typeface is ever used unless a font is named on the command line

`assets/skins.json` typesets, `scripts/render_cv.py:404` (`_face_for`), `:1731`

All five typesets are `Georgia, 'Times New Roman', serif` or `'Helvetica Neue', Arial,
sans-serif`. None of them matches an entry in `assets/fonts.json`, so `_used_faces()`
returns nothing, nothing is embedded, and the substitution check short circuits to
"nothing missing".

Reproduced: a default `--pdf` run on this Linux session produced a PDF set in
LiberationSerif and LiberationSans, exited 0, and reported those faces as if they were
correct.

This is the make-or-break promise. The PDF is meant to be exactly what the studio shows,
including the typeface, and the refusal is meant to catch a substitution. Neither holds
on the default skin. It only works when `--head-font` and `--body-font` are passed, which
the studio's own copied command does include, but which no default path does.

Fix: map the typesets onto real bundled families, or make `_wanted_faces` refuse when it
resolves to zero faces while the typeset names non-generic families.

### B2. A CV with the dates on their own line refuses to render

`scripts/render_cv.py:160` (date consumed, `role["src"]` not incremented), `:334`, `:1895`

The parser's own comment says almost nobody writes `### Title | 2023 to present`, and that
the dates usually sit on the line under the heading. That shape is counted on the way in
and not on the way out, so the line-count guard refuses.

Reproduced on a plain four-section CV: `REFUSING TO WRITE. 7 content lines in the
markdown, 6 accounted for.` The error blames the person's file.

Fix: `role["src"] += 1` when the date is taken from its own line.

### B3. The studio's line ids and the renderer's line ids do not match

`assets/studio.html:629` (`SEC` slugs) vs `scripts/render_cv.py:879` (`sid = slug(s["title"])`)

The studio hardcodes section prefixes. The renderer derives them from the heading text. So
`## TRAINING AND CERTIFICATIONS`, which is the heading in the skill's own `templates/cv.md`,
becomes `training-and-certifications` in the renderer and `training-certifications` in the
studio. `## EMPLOYMENT HISTORY` becomes `employment-history` in the renderer and
`professional-experience` in the studio.

Every decision made on those lines is silently dropped by `--decisions`. The studio's Final
view shows one thing and the PDF prints another.

Fix: emit the renderer's slug per section into the studio's CV block and use it instead of
the constants.

### B4. A multi paragraph profile is one line in the studio and several in the renderer

`scripts/build_studio.py:80`, `assets/studio.html:1299` vs `scripts/render_cv.py:948`

The studio joins all profile paragraphs into `profile/0`. The renderer emits `profile/0`,
`profile/1` and so on. Taking the profile off in the studio still prints paragraph two.
Editing it prints the rewrite plus the original paragraph two.

`templates/cv.md:8` invites three short paragraphs, so this is the documented shape.

Fix: key the profile per paragraph in `cv_block`.

### B5. Skills edits do not print in four of the six skills treatments

`scripts/render_cv.py:704` (chips, rings, bars, dots read `g["items"]`) vs `:696` (list,
columns read `d_text`)

A group rewritten in the studio prints its original wording under `bars`, `dots`, `rings`
and `chips`. Reproduced: an edit to `key-skills/technical` prints correctly as a list and
prints the old text as bars. The removed skill is still on the page and the new one is
absent, with no warning.

The studio has a comment at `assets/studio.html:1373` saying this exact bug was fixed,
in the studio only.

Fix: resolve `g["items"]` from `d_text` once at the top of `_group_html`, before the mode
branches.

### B6. The person's files default to a folder inside the plugin

`scripts/paths.py:84`, `SKILL.md:562`, `README.md`

`resolve()` falls back to `<plugin>/skills/resu-studio/data/`. That folder already exists
on disk, so the fallback has fired at least once. `facts.md`, `answers.md`,
`documents.json` and every PDF land there by default, and a plugin update replaces that
folder.

Worse, the override that is supposed to prevent this, `data-location.txt`, also lives
inside the plugin folder, so the update deletes the pointer too. After an update the skill
quietly resolves back to the default, finds no `facts.md`, and rebuilds a history that
should have been read.

README says the opposite of what the code does: "Your history and your finished documents
do not live inside the plugin."

Fix: last resort should be outside the plugin tree, for example `~/.resu-studio/`. Read
and write the pointer from a stable location outside the plugin. Warn on every call when
the resolved folder will not survive an update.

### B7. A Windows path in `data-location.txt` creates a junk folder and reports success

`scripts/paths.py:62`, `:49`, `:79`

`D:\Users\Jane\Documents\CV` is not recognised as absolute on Linux, so `os.path.abspath`
prepends the working directory, and `_usable()` then creates a single directory whose
literal name contains the backslashes. `resolve()` returns it with
`survives_an_update = True` and `paths.py` prints "a plugin update will not touch it."

Everything then lands in a throwaway directory inside the session, under a name nobody
will find, while the tool reports success. `~/Documents/...` has the same problem: it
resolves to the session's home, not hers.

Fix: reject any line matching a drive letter or containing a backslash, name the mounted
equivalent in the message, and require the parent to already exist rather than creating it.

### B8. A missing `assets/paginate.js` produces a blank document, silently

`scripts/render_cv.py:1476` (`_asset` returns `""` when absent), `:1458`

All content sits in `<div id="src" hidden>` and the paginator moves it into `#doc`. With
the script missing, or with JavaScript off in the fallback "open the HTML and save as PDF"
route the advice text recommends, the page renders nothing. Reproduced: a 1073 byte PDF
with zero text operations. `to_pdf.py:187` only rejects PDFs under 1000 bytes, so it slips
through, and with B1 the font check does not catch it either.

Fix: make a missing `paginate.js` a hard failure, and add `#src{display:block}` inside a
`<noscript>`.

## Serious

Wrong in a way the person can see, or wrong in a way that wastes their work.

### S1. `--skills-place` silently deletes a whole skills group on a layout with no sidebar

`scripts/render_cv.py:781`, `:1395`. Reproduced: `--layout classic --skills-place
"Domain=side"` drops the Domain group and still prints "Nothing added, nothing dropped."
The studio persists `groupPlace` across a layout switch and emits the flag regardless, so
this is reachable from ordinary use.

### S2. Two skills groups sharing a heading collide on one id

`scripts/render_cv.py:683`. Two `**Tools:**` lines both get `key-skills/tools`, so one
removal deletes both. Unlabelled lines all collapse to `key-skills/`.

### S3. The studio's paginator is an older copy than the print one

`assets/studio.html:743` vs `assets/paginate.js:28`. The only difference across 26 diff
lines is that the studio's copy does not wait for `document.fonts.ready`. The studio also
loads its typefaces from Google Fonts while the print embeds them locally. Page breaks in
the preview and the print can therefore differ, which is the drift the whole file exists to
prevent.

Fix: generate the studio's inlined copy from `assets/paginate.js` at build time.
`assets/markup.js` has drifted the same way and needs the same treatment.

### S4. Lines the person wrote are missing from the hand to Claude block

`assets/studio.html:3341` (`handoffText`) never reads `S.adds`, although the drawer's own
subtitle promises "what you added" and the badge counts them. Someone who copies the block
rather than saving the JSON loses every added line, with a count that says otherwise.

### S5. Reordering bullets in the studio never reaches the print

`assets/studio.html:1202` stores `S.bOrder`; neither the decisions file nor the copied
command carries it, and `render_cv.py` has no such option. The Final view is documented as
exactly what prints. Either carry the order through or take the buttons out.

### S6. Skills edits are lost when the render regroups

`scripts/render_cv.py:753` does an exact id lookup; the studio records a fingerprint so an
edit survives regrouping in the preview. `--group` and `--decisions` are emitted together
by the studio's copied command, so this is the ordinary path.

### S7. Two applications can overwrite each other

`scripts/documents.py:114`, `scripts/render_cv.py:1554`. Identity is role plus source
basename. The employer is collected and then used in neither the filename nor the ledger.
Two "Project Manager" applications, both assembled into `cv-tailored.md`, both rendered the
same day, produce the same filename, and `protect()` returns `None`. The earlier PDF is
overwritten with nothing printed. README promises the opposite.

### S8. The Phase 6 rebuild command empties the Score tab

`SKILL.md:489` passes only `--cv --role --employer` and an optional `--asks asks.json` that
nothing in the skill ever writes. `build_studio.py` then wipes the score, the proposals and
the achievements, and prints `asks : 0 (not scored yet)`. The prose two dozen lines earlier
promises the person watches the score move.

Fix: the Phase 6 command needs the same `--scorecard --asks-md --facts --proposals
--achievements` that Phase 3 and Phase 4 use.

### S9. `--role` is optional, and omitting it shares one browser store across every application

`scripts/build_studio.py:388`, `:486`. The key falls back to the person's name, so every
application shares it, while the build prints "so this application cannot see any other".

### S10. A malformed `cv-decisions.json` produces a Python traceback

`scripts/render_cv.py:1838`, `:761`, `:828`, `:1842`. Reproduced three ways. This file is
routinely hand saved from a pasted block, so a small shape error is likely.

### S11. Bars, dots and rings drop the proficiency word from the extractable text

`scripts/render_cv.py:713`. `Python (Advanced, 10+ yrs)` extracts as `Python (10+ yrs)`,
and as `4 Python (10+ yrs)` under rings. `references/ats.md:80` promises the level prints as
text beside the drawing.

### S12. Editing a skills group prints its heading twice

`scripts/render_cv.py:698` does not strip the heading the studio seeded into the editor.
Output: `Technical:Technical: Python (Advanced); R (Master)`.

### S13. A proposal whose `Line:` matches nothing is counted as if it landed

`scripts/build_studio.py:277`, `:445`. Only a missing `Line:` is reported. A stale or
typo'd one is loaded, counted, drawn against an empty stub, and its "Use this" writes a
mark the renderer will never match.

### S14. Content inside a recognised section that the studio cannot hold is dropped in silence

`scripts/build_studio.py:80`, `:82`, `:94`. A profile written as bullets, a skills section
written as plain bullets, and an intro paragraph inside the experience section all vanish
from the studio with an empty `dropped` list. The renderer prints all three. SKILL.md:375
says saying otherwise is the worst thing the skill can do.

### S15. `fetch_fonts.py --check` reports every bundled family as missing

`scripts/fetch_fonts.py:113`. It looks for `<key>-400.woff2`; the shipped files are named
`lora-v37-latin-regular.woff2`. So `--check` prints 0 of 18 covered and tells the person to
go online, while the renderer's looser matcher does find all 18. The refusal message points
people at this check.

### S16. `check.py` is listed twice and invoked nowhere

`SKILL.md:675` is the only mention. Its argument, "workbench folder", is defined nowhere,
its documented `[variant]` parameter is ignored, and a missing folder raises
`FileNotFoundError` with the same exit code as "faults found". It also opens files as
strict UTF-8, so a CV saved from Word in cp1252 crashes the whole run.

### S17. `facts.md` is passed as a bare relative path everywhere

`SKILL.md:312`, `:371`. A relative path resolves against the session's working directory,
which is thrown away at the end of the session. `paths.py` has no machine readable mode
that would print the absolute path for a command line.

Fix: add `--facts`, `--data` and `--documents` flags to `paths.py` that print one bare path,
and use them in every command block.

## Documentation and instruction defects

These do not break the code. They make an instruction following model do the wrong thing.

**Contradictions**

- `SKILL.md:304` says the studio is built at the end of Phase 3. `SKILL.md:666` says
  Phase 6. Phase 3 is right.
- `SKILL.md:288` gives seven state words and says all three surfaces use them.
  `references/scoring.md:7` gives five, `:131` gives six, `:178` says seven. The counting
  rule at `scoring.md:41` has no home for `off`, so the headline number is undefined.
- `templates/scorecard.md:43` bans anything but the seven words. `:67` then uses
  "not yet worked out" in its only worked example, and the `counts:` key at `:14` is
  `not_yet_worked_out`.
- `references/proposing-changes.md:10` gives the canonical proposal entry without `Line:`,
  which `SKILL.md:344` calls mandatory and `build_studio.py:452` drops entries for.
- `SKILL.md:197` says the CV goes into `sources/`. `SKILL.md:254` and `paths.py:129` say
  `cv-source/` under the resolved folder. `sources/` is relative to nothing.
- `SKILL.md:241` says to record the scoring depth in the scorecard's frontmatter in
  Phase 1. The scorecard is written in Phase 3 and `templates/scorecard.md` has no `depth`
  field.
- `SKILL.md:311` builds the studio from a markdown CV that no earlier phase produces.
  Phase 1 only extracts `.txt`, and `build_studio.py:400` refuses markdown without a
  `# Name` heading.
- `SKILL.md:358` says a rebuild replaces the studio. `SKILL.md:500` says it keeps the first
  under a dated name. The script's rule is that keep aside applies to a different
  advertisement only.
- `references/rendering.md:225` documents seven layouts, five of which do not exist in
  `skins.json`, along with two paragraphs that depend on them.
- `references/rendering.md:33` says the page fetches fonts from Google. `:540` says they
  have to be installed. `:628` says they are embedded as base64. The last one is right.
- `references/rendering.md:529` prescribes a manual PDF workflow that `--pdf` replaced.
- `references/ats.md:21` requires the name to be the first thing in the file and says to
  reject a layout that fails. `:53` says all eight sidebar layouts fail it. The default
  layout is a sidebar.
- `references/marking.md:63` calls Working and Final a switch. `SKILL.md:560` calls Final a
  tab. `rendering.md:527` puts Copy settings on a Working tab that does not exist.

**Wrong facts in the docs**

- `SKILL.md:676` says 350 skins. There are 900.
- `references/rendering.md:587` gives PDF filenames that are not what `_pdf_names` writes.
- `SKILL.md:96` says `--pdf-dir` relocates `facts.md` and the source CV. It only moves
  rendered output.
- `SKILL.md:534` says four of eight sidebar layouts open with the profile.
  `references/ats.md:54` names three.
- `SKILL.md:379` says the studio carries six sections. `references/achievements.md:5` and
  `SKILL.md:566` name three more that can be added.
- `references/proposing-changes.md:29` and `SKILL.md:669` promise eight worked before and
  after pairs in `references/rewriting.md`. That file deliberately has none, and says so.
- `references/scoring.md:146` refers to "the match file", which does not exist.
- `SKILL.md:337` lists a `Location` field the template does not have, and omits `Costs`
  and `Decision`, which it does.
- Achievement count is six in `SKILL.md:363`, four to six in `references/achievements.md:23`,
  and six only in `templates/achievements.md:17`.
- `references/rendering.md` has two sections duplicated word for word, and three drifting
  accounts of how `sidebar-top` should behave.

**The skill breaks its own voice rules**

`references/voice.md:11` bans em dashes and en dashes anywhere, including a sentence of
chat, and `scripts/check.py:17` enforces it. There are more than forty em dashes across
SKILL.md and the reference files, including inside blocks that are quoted to the person
(`SKILL.md:392`, `templates/answers.md:37`) and throughout `README.md`. The banned "X, not
Y" construction and the aphoristic closer are the house style of the reference files.

The cleanest resolution is to say plainly in `voice.md` that its rules govern what is
written for the person, then fix the quoted blocks and the README, which are person facing.

## Smaller items

- `build_studio.py:492` crashes when `--out` is a bare filename.
- `build_studio.py:247` coerces `condition` and `not a cv question` into `implied`, so a
  citizenship or licence condition is shown as a soft role description item.
- `build_studio.py:163` loses the first word of an ask whose scorecard cell does not start
  with an id.
- `assets/studio.html:2165` asserts a depth sentence the build never records, and counts
  unscored musts as scored in the same sentence.
- Skill levels are matched case insensitively by the renderer and case sensitively by the
  studio, so `(advanced)` rates in the print and does not in the preview.
- The studio's "By discipline" chip always yields zero groups, because
  `assets/regroup.json` is never swapped into the template.
- `render_report.py` advertises a `--palette` it does not have.
- `to_pdf.py:131` builds the `file://` URL by concatenation with no percent encoding, so a
  `#` or `?` in the output path prints the wrong document.
- `documents.py` keys its ledger on the bare basename, so two files with the same name in
  different folders share a record, and anything rendered with `--pdf-dir` is permanently
  reported as moved or deleted.
- `--date` and `--out` exist and are documented nowhere.
- The studio's copied command uses `python` and a different relative path than every
  documented example, and omits `--role`.
- Dead code: `render_cv.py:677` `_short()`, `to_pdf.has_real_fonts()`,
  `render_cv.py:1399` `data-spill` markers.

## What was confirmed sound

- `keep_aside()` renames rather than deletes, tries forty names, migrates the ledger record,
  and returns `None` on error.
- A broken ledger never blocks a render.
- An unrecorded file is treated as unknown provenance and kept.
- All seven scorecard states exist in the studio with distinct labels and colours, and
  `unscored` is excluded from the counts, from the must check and from the gap list.
- Both return paths exist in the studio, and the decisions JSON shape matches what
  `render_cv.py` reads, including added sections.
- All eighteen webfont families have both weights present in `assets/fonts/`, and the
  renderer's loose matcher resolves every one, so the offline promise does hold once a font
  is actually named.
- When a face really is substituted, both PDFs are deleted and the run refuses, exactly as
  the README says.
- `build_studio.py` reads the template fresh and never writes back to `assets/studio.html`.
